# Qdrant产品知识问答 Demo 演示脚本

建议演示5～8分钟。先演示本地检索，再在已确认资料外发和模型配置后演示生成回答。

## 1. 查看原始资料

打开清单中的《Qdrant常见客户异议及应对FAQ》，说明程序不是递归抓取所有文件，而是显式选择15份Qdrant资料和1份图文出差报告，并为内部资料、历史实验、模拟方案、案例解读和会议记录保存状态标签。

## 2. 查看切片、向量和Payload

进入“检索原理展示”，选择FAQ或售前手册中的一个片段。依次指出原文章节、切分结果、Point ID、512维向量的前8个数值及Payload。强调Embedding模型生成向量，Qdrant负责保存和检索；单个维度没有人工指定的业务含义。

## 3. 用自然语言提问

提问：“Payload过滤能否直接作为权限系统？”查看Top-K结果，展开命中的FAQ和过滤学习笔记。说明相似度分数是语义接近程度，不是答案正确率。

## 4. 换一种说法

改问：“只给数据加租户字段，就不会发生跨租户访问了吗？”比较命中文档是否仍围绕后端强制过滤、漏过滤风险和权限边界。

## 5. 加入过滤条件

用“Qdrant适合怎样的客户场景？”先查询全部资料，再把范围限制为“模拟场景方案”。说明向量检索寻找相关内容，Payload过滤限定哪些资料允许参与检索。

## 6. 展示带引用回答

只有在确认可向TrueFoundry发送“问题＋实际召回片段”后，启用回答模型并勾选外发确认。展示回答中的`[1]`、`[2]`如何与下方真实召回片段对应。资料不足时，回答应说明不足，而不是补造价格、SLA或客户事实。

## 三个推荐演示问题

1. `Qdrant是什么，在RAG里负责什么？`
2. `Payload过滤能不能直接替代权限系统？`
3. `开源版可以用于生产，客户为什么还可能考虑商业方案？`
